Créer une extension

Tout ce qu'il faut pour écrire, tester et publier une extension pour Ollama Chat React — du format exact attendu à une bibliothèque de fonctions documentées pour décrire ce que ton extension doit faire.

Vue d'ensemble

Une extension ajoute des instructions au modèle — au chat de base (et à Codex, qui partage le même modèle) ou à Control Me, selon la cible choisie. Elle ne contient ni code ni script exécuté : l'app n'a pas de bac à sable pour ça, donc plutôt que de faire semblant, le système reste volontairement déclaratif. Ce que tu écris est simplement ajouté au prompt système du modèle au moment où l'utilisateur active ton extension.

Concrètement, ça veut dire que la puissance d'une extension vient entièrement de la qualité de ses instructions : plus tu es précis sur ce que le modèle doit savoir, quels libellés chercher à l'écran, quel raccourci utiliser, quel ton adopter, etc., plus elle sera fiable. La section Bibliothèque de fonctions ci-dessous te donne un vocabulaire précis et déjà connu du modèle pour décrire des actions.

Le manifeste

Chaque version publiée d'une extension est stockée sous la forme d'un petit JSON, le manifest : 

{
  "target": "controlme",
  "system_prompt_addition": "…le texte que tu écris dans le champ Contenu…"
}
ChampValeursEffet
target "chat" ou "controlme" "chat" : ajouté au prompt système du chat de base (et donc aussi visible par Codex, qui l'étend). "controlme" : ajouté au prompt système d'une session Control Me — installée comme un skill que l'utilisateur peut activer avant de lancer une session.
system_prompt_addition texte libre Injecté tel quel — pas de parsing spécial, pas de syntaxe obligatoire au-delà du bon sens (voir la bibliothèque ci-dessous pour un vocabulaire recommandé).

Publier une nouvelle version d'une extension existante (même nom, nouveau numéro de version) ajoute simplement une nouvelle ligne de version — les anciennes restent consultables, la dernière est celle installée par défaut.

Bibliothèque de fonctions

Le contenu d'une extension reste du texte libre — il n'y a pas de vrai interpréteur qui exécute une syntaxe. Ce qui suit est une convention de vocabulaire : une liste de fonctions nommées, avec leurs paramètres exacts, que tu peux citer directement dans le champ Contenu pour décrire précisément une action au modèle. Chaque fonction correspond à une capacité réellement câblée dans l'app (les mêmes outils que le modèle utilise déjà, juste documentés ici sous un nom simple à écrire). Utiliser ce vocabulaire rend tes instructions plus fiables qu'une description en prose libre, parce que le modèle reconnaît directement à quel outil chaque fonction correspond.

Comment s'en servir concrètement : écris tes instructions normalement, et cite une fonction entre parenthèses pour lever toute ambiguïté. Exemple : « Pour lancer une recherche, clique d'abord sur la barre de recherche en haut de la fenêtre (clique(x, y) sur sa position), puis tape la requête (tape("...")), puis valide (touche("Entrée")). »

Pour une extension Control Me (target: "controlme")

Les coordonnées sont toujours normalisées de 0 à 999 sur la largeur et la hauteur de l'écran (0 = bord gauche/haut, 999 = bord droit/bas) — c'est le même repère que celui déjà utilisé par l'outil de contrôle intégré, quelle que soit la résolution réelle de l'écran de l'utilisateur.

clique(x, y)
Clic gauche simple à la position donnée.
→ action click
double_clique(x, y) / triple_clique(x, y) / clique_droit(x, y) / clique_milieu(x, y)
Variantes de clic — double/triple clic, clic droit (menu contextuel), clic molette.
→ double_click / triple_click / right_click / middle_click
deplace(x, y)
Déplace le curseur sans cliquer — utile avant un survol qui affiche un tooltip/menu.
→ move
glisse(x1, y1, x2, y2)
Glisser-déposer d'un point à un autre (déplacer un fichier, une fenêtre, un curseur de réglage…).
→ drag_and_drop
tape("texte")
Tape du texte au clavier à l'endroit où se trouve le focus (clique d'abord sur le bon champ).
→ type
touche("Entrée" | "Échap" | "Tab" | "Suppr" | …)
Appuie une seule touche nommée.
→ press_key
maintiens("Maj") / relache("Maj")
Maintient ou relâche une touche indépendamment (pour une sélection au clavier, un tir maintenu dans un jeu, etc.) — toujours relâcher ce qui a été maintenu avant la fin.
→ key_down / key_up
raccourci("Ctrl+S")
Combinaison de touches pressées puis relâchées ensemble.
→ hotkey
molette(x, y, delta)
Fait défiler à la position donnée — delta positif = vers le bas.
→ scroll
attend(ms)
Pause explicite avant l'action suivante — utile après avoir lancé une app qui met du temps à s'ouvrir.
→ wait
lit_interface()
Lit la structure d'accessibilité Windows de la fenêtre au premier plan (labels, types, positions déjà normalisées) — à préférer à une capture d'écran pour localiser précisément un élément dans une fenêtre standard (pas un jeu ou un canvas dessiné à la main).
→ read_ui_elements
lit_base_connaissances()
Lit le contenu du dossier de connaissances locales de l'utilisateur (fichiers .txt/.json/.sql), s'il en a configuré un.
→ read_knowledge_base
retiens(fait, categorie)
Mémorise durablement un fait appris sur l'utilisateur pendant la session, pour les sessions futures.
→ remember_fact

Pour une extension Chat/Codex (target: "chat")

Le chat de base et Codex ont déjà leur propre jeu d'outils fixe (lecture/écriture de fichiers, commandes PowerShell, questions à l'utilisateur) — une extension ciblant "chat" ne peut pas ajouter de nouvel outil, seulement du contexte et des instructions qui influencent comment le modèle utilise ceux qui existent déjà. Cite-les directement par leur nom si tu veux orienter leur usage :

Nom de l'outilCe qu'il fait
read_fileLit un fichier texte (chemin absolu).
list_dirListe le contenu d'un dossier (un niveau).
write_fileCrée ou écrase un fichier entièrement.
edit_fileRemplace un passage précis d'un fichier existant.
run_powershell_commandExécute une commande PowerShell.
ask_user_questionPose une question à l'utilisateur et attend sa réponse.

Exemple d'instruction utile ici : « Avant toute modification d'un fichier de configuration, préfère edit_file à write_file pour ne changer que la ligne concernée » — ça reste une préférence textuelle, pas une nouvelle capacité.

Exemples complets

Extension Control Me — assistant Spotify

{
  "target": "controlme",
  "system_prompt_addition": "Tu aides l'utilisateur à contrôler Spotify (application de bureau Windows). La barre de recherche se trouve généralement en haut de la fenêtre — utilise lit_interface() pour la localiser précisément avant de cliquer, plutôt que de deviner sa position. Pour lancer une recherche : clique(x, y) sur la barre, tape(\"nom de la chanson\"), touche(\"Entrée\"). Le raccourci raccourci(\"Ctrl+Espace\") met en pause/reprend la lecture sans avoir besoin de chercher le bouton à l'écran."
}

Extension Chat — style de revue de code

{
  "target": "chat",
  "system_prompt_addition": "Quand on te demande de revoir du code, structure toujours ta réponse en trois parties : Bugs potentiels, Lisibilité, Suggestions optionnelles. Si tu utilises edit_file pour appliquer un correctif, explique en une phrase pourquoi juste avant de l'appeler."
}

Sécurité et revue

Avant publication, le contenu est envoyé à Gemini 3.7 avec pour instruction de détecter toute tentative de manipulation cachée du modèle (vol de données, désactivation de garde-fous, incitation à des actions dangereuses...). Un verdict unsafe bloque la publication — rien n'est enregistré. Un verdict safe publie l'extension, mais elle reste marquée non officielle (badge orange) tant qu'aucune revue humaine explicite n'a eu lieu : ce n'est qu'une IA qui a regardé, pas une personne.

Ce que la revue ne garantit pas : une extension jugée sûre peut quand même être de mauvaise qualité, mal écrite, ou simplement inefficace — la revue de sécurité ne juge que l'intention malveillante, pas la qualité. Les utilisateurs sont explicitement prévenus qu'installer une extension non officielle se fait à leurs risques et périls.

Publier

  1. Active le mode développeur depuis le menu de ton compte (en haut à droite de n'importe quelle page du site).
  2. Ouvre l'espace développeur, remplis le formulaire de publication.
  3. Fournis une clé API Gemini (Google AI Studio) — elle sert uniquement à l'examen de sécurité, jamais stockée.
  4. Une fois publiée, ton extension apparaît immédiatement dans la marketplace, avec sa propre page.
  5. Le bouton « Ajouter » de sa page installe l'extension automatiquement dans l'app de l'utilisateur qui clique, sans étape manuelle de sa part.
